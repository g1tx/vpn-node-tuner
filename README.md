# VPN Node Tuner

Настройка Ubuntu для VPN-нод **Xray / VLESS + REALITY / Remnawave**. Подходит для небольших VPS с 1 vCPU и 1–2 ГБ RAM.

## Быстрый старт

Подключись к серверу по SSH и выполни **одну команду**:

```bash
curl -fsSLo tune.sh https://raw.githubusercontent.com/g1tx/vpn-node-tuner/main/tune.sh && sudo bash tune.sh --apply
```

Готово: тюнер применит настройки, проверит результат и сохранит их после перезагрузки. Перезагружать сервер для применения не нужно. Если работаешь под `root`, команда тоже подходит.

Нужна **Ubuntu 24.04**, установленный `curl` и доступ `root` или `sudo`. Команда скачивает скрипт в текущую папку; сохрани его для проверки настроек и отката.

Тюнер настраивает систему для уже установленной VPN-ноды. Xray, Docker и панель Remnawave устанавливаются отдельно.

## Что он делает

- Настраивает максимальные TCP-буферы с учётом RAM, включает автоподстройку и обнаружение проблем MTU.
- Сохраняет работающий алгоритм TCP и очереди `fq` / `fq_codel`; для `fq` включает pacing.
- Сохраняет настройки после перезагрузки и исходное состояние для отката.

По умолчанию используется сбалансированный профиль. Скрипт не перезапускает Docker и Xray. Фиксированного ограничения скорости нет.

## Полезные команды

Запускай из папки, в которую скачан `tune.sh`.

| Действие | Команда |
|---|---|
| Посмотреть текущие настройки | `sudo bash tune.sh --diagnose` |
| Вернуть состояние до первого применения | `sudo bash tune.sh --revert` |
| Попробовать BBR + fq | `sudo PROFILE=bbr bash tune.sh --apply` |
| Перейти со старой версии v1 | `sudo bash tune.sh --apply --migrate-legacy` |

Если тюнер сообщает об обнаружении старой версии, используй команду перехода из таблицы. Она сохраняет старые файлы, но ранее изменённые настройки Docker и посторонние системные параметры требуют отдельной проверки.

## Чего ждать от результата

Универсального ускорения нет: результат зависит от CPU, маршрута и нагрузки. Поэтому тюнер не включает BBR принудительно — на проверенном сервере он иногда уступал штатному режиму.

В проверке с ограничением RAM до 1 ГБ Xray в Docker выдержал 30 параллельных скачиваний в течение двух минут без OOM. При полной нагрузке задержка всё равно росла. Это проверка конкретного сценария, а не гарантия скорости для любых 30 пользователей.
