## 📖 Что это

`xray-reality-tuner` — это **один bash-скрипт**, который приводит сетевой стек Linux в порядок для работы прокси/VPN exit-ноды на базе **Xray-core** (VLESS + REALITY) внутри **Docker** (в т.ч. панель **Remnawave**).

Вместо того чтобы вслепую копировать чужие `sysctl`-конфиги, скрипт **сам определяет** ваше железо (CPU, RAM, сетевую карту, скорость линка) и подбирает **безопасные, выверенные** значения. Никакого cargo-cult — только параметры, которые реально имеют смысл.

> 💡 Скрипт **идемпотентен** (можно запускать сколько угодно раз) и имеет **полный откат** одной командой.

## ✨ Что делает скрипт

Коротко по делу — что включается «под капотом»:

| Категория | Что настраивается |
|-----------|-------------------|
| 🚀 **Скорость TCP** | Включает **BBR + fq** — главный прирост на потерях и длинных RTT. TCP Fast Open, MTU probing, window scaling, SACK. |
| 📦 **Буферы сокетов** | Размеры рассчитываются от **реальной скорости линка** (BDP), а не «на глаз». Авто-тюнинг приёма. |
| 🔗 **Conntrack** | `nf_conntrack_max` и hash-таблица под вашу RAM — чтобы таблица соединений не переполнялась под нагрузкой. |
| 🎯 **Очереди и backlog** | `somaxconn`, `syn_backlog`, `netdev_backlog` — чтобы не терять соединения на всплесках. |
| 📂 **Лимиты файлов** | Поднимает `nofile` (до 1–2 млн) для тысяч одновременных подключений. |
| 🧩 **Раскладка по ядрам** | RPS/XPS с учётом **NUMA**, аппаратные offload'ы (GRO/TSO), ring buffers, RSS-каналы — для multi-Gbit. |
| 🐳 **Docker** | Аккуратно патчит `daemon.json` (ротация логов, ulimits, live-restore) и поднимает `TasksMax` для Xray. |
| 🛡️ **Безопасность** | Анти-спуфинг, отключение redirects/source-route, ICMP-hardening. |
| 💾 **Память/IO** | `swappiness`, dirty-ratio, ARP/neigh таблицы — стабильность под большим числом контейнеров. |

## 🧠 Авто-адаптация под железо

Скрипт определяет один из трёх профилей и масштабирует значения:

| Профиль | Когда | Под что заточен |
|---------|-------|-----------------|
| 🟢 **Low** | RAM ≤ 4 ГБ или CPU ≤ 2 | Слабые VPS — экономия памяти, без переразмеривания |
| 🟡 **Medium** | RAM ≤ 32 ГБ и CPU ≤ 8 | Типичные ноды — баланс throughput / RAM |
| 🔴 **High** | всё что выше | Bare-metal / 10G+ — максимальная пропускная способность |

Дополнительно учитываются: модель драйвера NIC (физический vs `virtio_net`), скорость линка, число NUMA-узлов.

## 🚀 Установка

### Способ 1 — быстрый старт (one-liner)

```bash
curl -fsSL https://raw.githubusercontent.com/USERNAME/xray-reality-tuner/main/tune.sh -o tune.sh
sudo bash tune.sh
```

### Способ 2 — через git

```bash
git clone https://github.com/USERNAME/xray-reality-tuner.git
cd xray-reality-tuner
sudo ./tune.sh
```

> 📌 **Замените `USERNAME`** на ваш GitHub-логин после публикации.

### ✅ Рекомендуемый порядок

1. Установите панель / ноду (Remnawave, Docker, Xray).
2. Запустите тюнер: `sudo ./tune.sh`
3. Готово. Скрипт можно запускать повторно в любой момент — он идемпотентен.

> ⚠️ Лучше запускать **после** установки Docker — тогда подхватятся настройки conntrack, `daemon.json` и лимиты Xray.

## ↩️ Откат

Вернуть всё к состоянию по умолчанию:

```bash
sudo ./tune.sh --revert
```

Удаляются все созданные конфиги; дефолты ядра возвращаются после перезагрузки.

## 🎛️ Тонкая настройка (необязательно)

Поведение можно переопределить через переменные окружения:

```bash
# Примеры
sudo NIC=eth1 ./tune.sh                  # явно указать сетевую карту
sudo BANDWIDTH_MBIT=10000 ./tune.sh      # задать скорость линка вручную
sudo DISABLE_IPV6=0 ./tune.sh            # НЕ отключать IPv6
sudo ALLOW_DOCKER_RESTART=0 ./tune.sh    # не перезапускать Docker (отложить вручную)
```

| Переменная | По умолчанию | Назначение |
|------------|--------------|------------|
| `NIC` | автоопределение | Сетевой интерфейс |
| `BANDWIDTH_MBIT` | из системы | Скорость линка (для расчёта буферов) |
| `DISABLE_IPV6` | `1` | Отключить IPv6 (`0` — оставить) |
| `RP_FILTER_MODE` | `2` | Reverse-path filter (`2` = loose, безопасно для WARP/policy-routing) |
| `TCP_FASTOPEN` | `3` | TCP Fast Open |
| `CT_BOTTLENECK` | `0` | Включить максимальный hashsize conntrack |
| `ALLOW_DOCKER_RESTART` | `1` | Разрешить перезапуск Docker для применения настроек |

## ❓ FAQ

<details>
<summary><b>Это ускорит мой VPN?</b></summary>

Главный прирост даёт **BBR** — заметен на сетях с потерями и большим RTT (мобильные клиенты, далёкие сервера). На чистом гигабите рядом разница минимальна. Остальные параметры — это в первую очередь **стабильность** под нагрузкой, а не «иксы скорости». Честно: волшебного «×10» не будет.
</details>

<details>
<summary><b>Не сломает ли это сервер?</b></summary>

Скрипт использует безопасные значения, не трогает SSH-доступ и имеет `--revert`. Все изменения — в отдельных drop-in файлах (`/etc/sysctl.d/`, `/etc/security/limits.d/`), а не в системных конфигах.
</details>

<details>
<summary><b>Конфликтует ли с панелью Remnawave?</b></summary>

Нет. Единственное пересечение — BBR/fq, и значения совпадают. Запускайте тюнер **после** установки панели.
</details>

<details>
<summary><b>Можно ли запускать повторно?</b></summary>

Да. Скрипт идемпотентен — повторный запуск просто перезапишет конфиги актуальными значениями.
</details>
