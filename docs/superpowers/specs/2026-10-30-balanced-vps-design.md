# Balanced Ubuntu VPN exit tuning

Approved scope: user authorized implementation and unrestricted experiments on a disposable SSH server on 2026-10-30. Target Ubuntu 24.04, 1 vCPU, 1 GiB RAM, 1 Gbit advertised channel, around 30 concurrent mixed-traffic users. Optimize useful throughput with responsive latency under load. Do not claim a universal optimum or guaranteed speed gain.

Keep a standalone Bash entry point tune.sh, with --dry-run, --diagnose, --apply (default), --revert, --help. Strictly validate all supplied values before host mutation. Plan buffers from explicitly supplied bandwidth and RTT or conservative fallback; NIC advertised speed is not measured Internet capacity. Preserve kernel aggregate TCP/UDP memory heuristics, IPv6, forwarding, route policy, Docker daemon and NIC offloads by default. Enable available BBR, TCP receive autotuning and MTU blackhole probing. Raise bounded socket maxima without enormous default allocations. Apply fq on actual supported egress queues, preserve mq root, and refuse to replace custom traffic-control hierarchies. No automatic shaper, busy polling, CPU governor, ring/channel resizing or extra RPS on single CPU.

Persist a root-owned runtime queue helper/service and sysctl drop-in. Snapshot all managed files and runtime sysctls/qdisc settings before first application. Repeated runs must preserve the original snapshot. Errors must not report success; failed apply rolls back its partial changes, and original preinstallation state is available via --revert. Reboot persistence and restoring pre-existing managed files must be tested. Legacy v1 installations must be detected and require explicit migration, preserving backups and warning about limitations of old rollback. Docker network mode and actual limits are diagnosed, changes to Docker daemon are opt-in or manual. No automatic daemon restart.

Validation: Bash syntax, ShellCheck, regression tests for parsing/calculation/apply/repeat/revert/failure, live apply/revert, service persistence/reboot and controlled TCP load experiments. Internet and isolated namespace tests have clearly stated limits. Benchmark reports include throughput and median/tail latency, CPU/memory, not only idle ping. No credentials in repository or artifacts.
